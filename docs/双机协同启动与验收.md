## 1. 完整启动（一条命令）

前置：Go2 已连接机器人和共享 Wi-Fi、按原流程站稳、预检期间静止，现场急停可用；Ranger 可同时或稍后按第 3 节准备真实硬件、定位/Nav2、bridge 和 agent，Go2 本机准备不等待它先完成。需要图形桌面、交互式 Bash 与 `gnome-terminal`。

在 Go2 控制电脑桌面的主终端 G0（交互式 Bash）执行；以下绝对路径命令允许任意执行目录，脚本自动加载环境，无需另行 source。已有旧任务时，先按第 8 节暂停、确认停稳及原生动作终态、正常退出旧任务节点，再启动新一轮：

```bash
export COOP_SETUP_FILE=/home/isee-pst/unitree_ros2/VLM_Nav/build/go2-single-parity-20261025/overlay/install/local_setup.bash
bash /home/isee-pst/unitree_ros2/VLM_Nav/scripts/cooperative.sh go2 preflight
```

预检退出0且报告安装匹配、live_gates为空、API环境齐全后，才在同一终端运行以下原完整入口；失败则先处理报告，不继续叠加启动。各组件窗口保持运行：

```bash
bash /home/isee-pst/unitree_ros2/VLM_Nav/scripts/start_go2_cooperative.sh
```

```bash
cd /home/isee-pst/unitree_ros2/VLM_Nav
bash scripts/start_go2_cooperative_task.sh restart
```



**该命令会自动 ARM，并发起一次真实任务。** 顺序为：live 预检 → 相机 → 传感器预检 → 底层 → RViz → DISARMED Sport → NAV_READY/输入检查 → 任务 bridge → ARM → agent → 两端健康待命 → coordinator/watch → 一次 start。

- 无需输入 CAMERA/START/READY/CURRENT/ARM；SSH 未免密时仍需输入相机凭据。未定位时，在 RViz 用 **2D Pose Estimate** 设置实车实际位姿；已有有效定位不要重置。
- System先等AMCL定位就绪，再启动Nav2及supervisor；入口等待NAV_READY=true后才读取Keepout参数。当前等待上限120秒，期间保持组件窗口运行并完成真实位姿初始化；超时先查原窗口，勿叠加重跑。
- 待命检查持续等待，每 5 秒输出原因；两端各至少 3 条新鲜推进的健康 WAITING_PEER/STANDBY、地图身份与发布者/QoS 正确才继续。不会自动解除 PAUSED、复位 FAULT 或重启旧组件。
- 返回 `accepted=True`（或 `accepted=true`）及 `task_id` 仅表示开始请求受理；随后等待双方当前任务 `SYNCED` 才派工，整轮成功按第 7 节判断。失败查看对应窗口和 `build/go2-field/cooperative-task.<随机标识>/`，不要重复 start。
- 组件窗口保持运行。Ctrl+C 退出等待、关闭主终端或 watch 均不会自动暂停任务或 DISARM；停止方法见第 8 节。
- 原 watch 窗口现为“Go2 当前状态”，自动显示 Go2 状态、完整原因及任务阶段；无需重建现有 overlay，已打开的旧 watch 不会热更新。

Go2正式开始本地搜索后，会先在停稳状态识别当前朝向的一帧新鲜相机图像。当前目标有有效位置则直接接近，未确认目标才进入探索选点；初始视角不先转圈。接口错误或缺少位置仍按原规则暂停/报告未定位，详见[当前相机策略](multi_agent/go2_runbook.md#2026-10-22-go2搜索前先识别当前相机)。

暂停与disarm：Ctrl+C 正常结束 两端 agents → Go2 coordinator → 两端 bridges。然后在 Go2 交互式 Bash 执行 DISARM，按提示确认 STOPPED：

### 1.1 脚本与分步入口

正式完整入口为 [start_go2_cooperative.sh](../scripts/start_go2_cooperative.sh)，调用现有硬件准备和任务编排，不改变各自的启动顺序。查看说明无需加载硬件环境：`bash /home/isee-pst/unitree_ros2/VLM_Nav/scripts/start_go2_cooperative.sh --help`。

| 当前需要 | 脚本 | 返回后如何继续 |
|---|---|---|
| 从本机准备到开始一轮，无确认词 | `start_go2_cooperative.sh` | 自动完成准备、等待和一次 start；不要再执行第 4～6 节启动命令 |
| 只准备硬件，保留人工确认 | `start_go2_cooperative_hardware.sh` | `HARDWARE_READY`、退出0、Sport=DISARMED 后，按第 5 节继续 |
| 硬件已通过，只准备任务组件 | `start_go2_cooperative_task.sh prepare` | 人工确认 ARM；`COOPERATIVE_READY` 后才按第 6 节 start 一次 |
| 任务组件已准备，只发一次开始请求 | `start_go2_cooperative_task.sh start` | 人工确认 START；记录返回的 task_id，观察本轮握手及执行 |
| 失败后保留健康底层，开始新一轮 | `start_go2_cooperative_task.sh restart` | 按提示退出旧任务组件并确认 DISARM；检查通过、两端重新待命后显式确认 START，见第 6.1 节 |
| 暂停或解除 Sport 使能 | `start_go2_cooperative_task.sh pause/disarm` | 两个独立动作，依第 8 节顺序执行；disarm 保留停稳确认 |

后四行是完整入口的分步替代方式，命令的绝对路径和环境见对应章节。完整入口仍需现场真实 RViz 初始位姿和必要的 SSH 凭据，不用自动坐标代替人工定位。

### 1.2 启动阶段、等待与成功判据

| 阶段 | Go2 行为与继续条件 | 正常观察及依赖 |
|---|---|---|
| 各自准备 | 核对安装/live gates，准备相机、传感器、System、RViz、DISARMED Sport；NAV_READY及输入检查通过后开启任务通信并 ARM | 只依赖本机；缺少本机健康条件时为 PREPARING，不能因 Ranger 尚未启动而伪造本机 nav_ready=false |
| 等待对方 | agent 本机健康、停稳且原生动作终态成立，即可 WAITING_PEER；收到合格对端等待/待命状态可 STANDBY | 双方 WAITING_PEER 可相互确认，无需先看到对方 STANDBY。两端各采到至少3条推进且新鲜的合格状态才继续 |
| 本轮任务握手 | 启动唯一 coordinator/watch，显式请求一次 start；接受 SYNCING 同步后各自立即公布新 task_id | 只认本轮干净状态。双方 `run_state=SYNCED` 且 `reply=SYNCED` 后才提交 SEARCH_AB；`ready` 此时仍为 false |
| 执行 | coordinator 先同步 SEARCH_AB 再向 Go2/Ranger 派工 A/B，严格验收后再处理各自 C | 执行后失联、健康异常或对端重启仍停车并锁存 PAUSED；通信恢复不自动续跑 |

等待 Ranger 的准备采样没有总超时，每5秒输出原因；允许对端晚启动、初始化或准备期重启。**600秒是从 StartTask 受理起的整轮预算，包含握手与执行**；握手不使用3秒取消期限，但确认必须新鲜。正常心跳2Hz，提交后的通信门槛3秒，消息年龄按接收端单调时钟计算。

watch 的“Go2 当前状态”同时显示 Go2 agent 的 `run_state/reason`、coordinator 的 `phase/reason`、各自任务 ID，以及 Go2 定位、导航和停稳报告。状态变化立即输出，未变化每5秒输出，保留完整原因和终端历史；两端 state/peer 仍可查看原始 agent 消息及 `reply`。状态可快速经过，不能用显示窗口代替逐条握手验收；`accepted/task_id` 只证明本轮请求受理，不能替代握手或 DONE 验收。

窗口每0.5秒按本机单调接收时间检查两路消息，以当前配置 `lost_timeout`（默认3秒）判断新鲜度。未收到显示“等待消息”，过期值标记“最后报告”；任务 ID 不一致会分别展示并提示。这里的 Go2 消息新鲜只表示 Go2 agent 持续报告，不能据此证明 Ranger 心跳已恢复；锁存的 PAUSED 不会因恢复通信自动解除。停稳字段是消息报告，不证明实体停稳或已 DISARM。

### 1.3 停在某一步时

| 现象 | 判断与继续方式 |
|---|---|
| `no state received` 或对端 PREPARING/nav_ready=false，仍在等待待命 | Ranger未启动或尚未就绪时可正常持续等待；查看对端本机原因，保持现有窗口，不重复运行完整入口 |
| NAV_READY 等待120秒超时 | Go2本机准备未通过，和等待Ranger是两阶段；查System/Sport及RViz真实定位，本次停止在硬件检查，不自动重试 |
| 安装与源码不一致、地图/模式不符、发布者重复、QoS错误 | 按预检或对应终端报告处理；不要把验证标志改true、冒用旧IDLE或强杀旧进程来继续 |
| 已ARM，按Ctrl+C退出准备等待；bridge/agent还运行 | 不再重跑完整入口或prepare；若继续同一准备，按第5节核对两端状态后只补缺少的coordinator/watch，再按第6节start一次；若结束则按第8节停稳/退出/DISARM |
| start返回accepted/task_id，或开始请求结果不明 | 不再发送第二次start；查看start.log、watch及两端同任务状态。PAUSED按第8节处理，不凭恢复心跳自动续跑 |

本轮日志目录启动时输出为 `build/go2-field/cooperative-task.<随机标识>/`；其中 `preflight.log`、`inspect.log`、`idle.json`、`start.log` 只在到达对应阶段后生成。组件退出时窗口会显示退出码，保留原窗口日志。

## 2. 配置与离线预检

[Cooperative_env.bash](../Cooperative_env.bash) 加载本机基础 ROS/硬件/API 环境，最后加载任务 overlay；[cooperative.sh](../scripts/cooperative.sh) 自行调用它，因此使用该脚本时无需额外 source。直接运行 `ros2`/`rviz2` 时，各节显式 source 环境。

Go2 每个独立终端都要选择 `build/go2-single-parity-20261025/overlay/install/local_setup.bash`；不指定也使用该默认安装；显式覆盖仍可选择另一实际安装，但预检会拒绝源码不一致。以下命令显式指定源码配置目录；另用现场副本时，各终端统一替换 `COOP_CONFIG` 或 source 的第二个参数。

G0 离线预检，执行后退出；不初始化 ROS、不请求模型、不发送运动：

```bash
cd /home/isee-pst/unitree_ros2/VLM_Nav
export COOP_SETUP_FILE="$PWD/build/go2-single-parity-20261025/overlay/install/local_setup.bash"
export COOP_CONFIG="$PWD/cooperative_ws/src/multi_agent_nav/config"
bash scripts/cooperative.sh go2 preflight
```

成功判据：退出 0、所有受检模块均 `matches_source=true`、两种 `sync_encodings` 均为 true、`api_environment_complete=true`、`live_gates=[]`、`motion_sent=false`。不满足则先处理报告中的具体项，不能为消除门槛随意改 true。

两端人工对照三种消息的 `schema_sha256`、同步编码兼容性、场景/目标及各机器人地图 ID/version。当前 Go2 源码配置为 `lab`，A=灭火器、B=灭火器、C=椅子；Ranger 本机使用的配置也须保持这组目标一致，以其实际预检核对。候选数量不证明实时可达。

网络：Go2 本地域 Domain0 走 `enp4s0`，共享 Domain40 走 `wlo1`；任务 bridge 使用按域绑定网卡的 XML，不用本地域 XML 替代。不桥接 TF、图像、costmap、速度或 action。
