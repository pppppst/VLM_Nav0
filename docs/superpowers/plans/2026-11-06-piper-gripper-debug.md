# Piper 独立夹爪调试实施计划

**目标：**按用户确认杯宽可用的要求继续调试，不重新讨论杯子尺寸；提供上位机 Python3.8/SDK0.6.2 的独立夹爪入口。此轮完成代码、离线检查、三包构建与可复制安装包，不自动部署或操作真机。

**设计：**复用 go2_piper_boot.py 的 USB 身份选择、只读 CAN 检查及关节反馈检查。新 Python 工具提供 inspect（只读持续监测）与 set（指定开口/力矩，最多发送一次，再持续观察）。set 查询驱动已有行程范围，不修改范围、零位或故障；这属于参数有效性校验，不重新验收杯宽。只调用 GripperCtrl，不控制六关节、底盘或开机服务。反馈中断/故障可等待恢复；已经尝试发送的命令即使异常也不自动重发。Ctrl+C 只结束监测和连接，既不释放也不失能，不能声称停止夹爪运动。

**方案选择：**使用现有 SDK 的独立工具；不引入 ROS 驱动或 MoveIt。完整自动抓取需要额外标定/规划，不属于本轮。用户已要求进入调试，按现有授权自主完成最小实现，不重复请求设计审批。

**文件范围：**新增 scripts/go2_piper_gripper.py、scripts/piper_gripper_debug.sh、test/test_piper_gripper.py；CMake 注册测试；runbook 维护构建与操作步骤，session_handoff 记录事实。保留 dirty 工作，直接在当前非主分支工作区做小范围新增，不迁移或丢失未提交依赖，不提交。

**入口与诊断：**Bash 入口使用指定 venv 和 -I，Python 显式加载同目录 boot helper。主终端只打印本轮日志路径；有图形终端时自动打开日志窗口，无图形 SSH 时提供独立 diagnostics 入口供第二终端查看。只读监测可并行，控制入口按 USB 身份加本机用户锁。日志 state/reason_class/reason 及反馈字段区分未就绪、已尝试命令、目标位置反馈和等待；不判定抓取成功。

**验证边界：**不会通过 CAN 故障自动重发夹持，不从 SDK 缓存初始值宣称成功；固件位置到目标也不是实物夹持证据。真实夹爪动作、物体夹持、上位机部署与 Python3.8 实机执行均另记，离线验证不代替现场结果。
