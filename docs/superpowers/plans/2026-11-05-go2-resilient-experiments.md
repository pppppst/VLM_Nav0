# Go2 全流程等待恢复实施计划

用户批准本会话方案：覆盖 Go2 单机、Agent、协同、manualnav2/VLMNav-go 及依赖入口；无限等待，暂停不消耗运行预算；组件崩溃等待人工修复，不自动重启；RViz 手动目标不自动重发；部分 Sport FAULT 自动复位/ARM。人工停止、接管、非法指令和身份错误不得自动解除。

## 约束

- 在当前 Go2 功能分支工作，保留历史证据，不提交、不部署、不启动现场节点或运动。
- 保持现有运动、定位、新鲜度、任务身份和 READY 条件；只改变等待与恢复，不放宽阈值。
- 复用恢复/诊断模块和既有依赖。未知程序异常、任务进度丢失、身份变更明确为本轮不可续接。
- 每项非平凡逻辑先失败用例再实现；最终新 overlay 构建含接口包、根包与协同包，更新入口默认和安装验证。
- 已授权 Codex 信箱协调 Ranger，但未授权远程启动或运动。需要用户回答时先提示音；代码交付播放5秒提示音乐。

## Task 1: Sport 恢复协议与状态机

新增 RecoverGo2Control.srv，实例ID/故障代次/阶段 PREPARE、RESUME、CANCEL 隔离旧请求；旧服务和状态文本兼容。typed fault codes 区分系统信号暂失、Sport/cmd端点缺失、cmd超时与非法指令、所有权冲突、外部控制。只有曾显式ARM的当前bridge实例可恢复。PREPARE只复位到DISARMED，RESUME复用原ARM检查；上层在调用RESUME前确认已有停稳/动作终态和除control_armed外的健康。人工控制及硬故障撤销代次；FAULT和恢复DISARMED期间同样生效。禁止旧速度重放。状态诊断发布实例/代次/故障类别及恢复资格。

## Task 2: 单机、协同恢复与客户端

扩展 ExperimentRecovery/AgentMachine/Coordinator/Runner 的软暂停；暂停、STOPPING及恢复握手冻结任务运行预算，新鲜度仍用真实时钟。共享代码默认旧行为，Go2 profile显式启用。Go2适配器接入恢复协议，动作异常区分能证明未发送/终态与身份不明；不得直接清空motion_fault。同task保留已完成阶段，旧future/视觉结果失效。人工取消禁止恢复。

## Task 3: 入口、旧VLM与诊断

动态预检、launch readiness及组件缺失无限等待，单次查询有限超时，不重复执行ARM/start。旧Go2 VLM暂时输入故障不永久FAILED或禁用，Ranger默认不变。组件人工替换依据已有新鲜数据、服务、唯一发布者与动作状态，不能只凭话题/PID；不接管人工进程清理权。所有总入口早期开启只读诊断，入口仅必要提示/路径。手动目标恢复待命。必要证据丢失保留缺口，不冒充完整成功。

## Task 4: Agent生命周期

取消1200/1270秒整段墙钟上限，保留单请求和取消收尾限制。搜索启动后框架故障转确定性守护、不取消独立搜索；取消仍停止，未启动时不擅自补启动。框架/原任务结果分别保留。

## Task 5: 协调、验证与交付

信箱对齐恢复原因、有效计时和双端握手；三次45秒无回复停止等待并列待同步。新增输入断流、TF、动作、复合故障、长等待、手动取消/接管、代次竞态、证据及组件替换测试。源码及安装验证，运行必要C++/Python测试，记录基线与新增。按runbook新建三包overlay，成功后切换默认环境和入口并检查安装，更新交接/运行指引。真机与双端现场恢复不自动执行。
