# Go2 等待恢复与状态终端实施计划

目标：单机实验的可恢复运行门槛关闭时先停止，保留本轮任务并等待恢复；运行计时排除暂停，另计累计暂停。新增只显示状态字段的诊断窗口，完成双包构建，不启动真机。

用户约束：不增加门槛，不改变启动用法；保留已有未提交工作，不提交。用户确认入口文件也不修改，保留 1270 秒宿主上限；现有 Agent planner 1200 秒外层上限亦未改动。

设计：复用当前搜索、停止、健康检查与事件记录。用独立恢复控制器管理暂停计时、停止与恢复条件；暂停期间运动 guard 拒绝新动作，取消的动作在停稳后重建，过期计划/视觉结果不复用。恢复同一 task，保留完成的探索记录。不会自动 ARM、reset_fault 或撤销人工取消。永久配置错误、程序异常与用户取消仍明确报告，不伪装成可自动恢复。

诊断：执行器启动只读文件监视窗口；原执行器每 0.5 秒更新状态文件，窗口不订阅 ROS、不打印配置文件。显示阶段、等待原因、实时健康字段、运行秒数、本次/累计暂停秒数、剩余运行预算及最终停车状态。窗口失败或关闭不改变任务。

实现范围：go2_check.py、go2_exploration.py、恢复/诊断小模块及定向测试；必要的 Agent 计时衔接待用户范围确认。原底层保护和阈值不改。构建到新 overlay，不覆盖现有安装。
