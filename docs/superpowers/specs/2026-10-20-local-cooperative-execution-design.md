# 本地 VLM 执行核心与最小协同入口设计

日期：2026-10-20。状态：用户已确认实现方向并明确要求进入实现。
依据：用户本轮修订及 `/home/isee-pst/Notes/单机框架.md`；本轮不共享 C，覆盖此前共享和共同 C 绑定要求。
不提交、不部署，不启动真机、ROS 节点、桥接、额外采集或真实 VLM 请求。

## 1. 目标与边界

- Go2 本地寻找 A，fake Ranger 本地寻找 B，各自完成接近验收后 READY；双方当前任务新鲜 READY 后进入 C 阶段。
- ABC 同图识别。C 仅进入发现者的本地当前任务缓存；C 阶段复用本地有效缓存，否则继续本地探索。
- Go2 完成 C 接近/模拟放入并整机退出后才允许 Ranger 接近/模拟放入/退出。
- RulePlanner 分配目标、阶段和顺序，不再为新模式逐个分配探索点；coordinator 保留命令、重发、超时、握手、心跳、READY 屏障及资源许可。
- 单机与协同复用同一公共探索、扫描、接近核心，不复制完整循环，不调用单机启动脚本子进程。
- 范围为 Go2 及公共包，使用 fake Ranger 验证；不实现或宣称接入本仓库不存在的 Ranger 硬件适配器。

## 2. 执行方式

复用现有 `go2_exploration.explore` 的选择、导航、扫描和接近逻辑，将等待 Future 的部分改为可逐步推进的公共执行核心。
原单机入口同步驱动该核心，保留现有行为；AgentRunner 在周期 tick 中推进同一个核心，每次等待均交回 ROS executor。
不在 VLM 等待期间阻塞心跳、命令接收、取消或停止检查。

核心显式接收 robot_id、当前任务身份、目标 ID、机器人自己的配置/adapter/地图及到达验收值。
Go2 和 fake Ranger 使用同一接口；Ranger 后续接入时提供自己的地图、候选几何、footprint、costmap、扫描及运动接口。
不把 Go2 的变换、绝对路径或几何参数作为 Ranger 默认值。

公共核心负责观察候选与 VLM 选 ID、观察结果、目标定位及接近距离逻辑。
协同导航仍经 AgentMachine 原许可与通行链办理；公共核心不能直接绕过 RegionGuard 或授予自身 token。
内部导航 goal_id 独立，当前 task_id、主 command_id 和许可 parent_command_id 保持关联。
门通行仍需整机退出和释放，再恢复原主任务；C token 贯穿接近、模拟放入及 EXIT。

## 3. 入口距离策略

| 入口 | 停稳后 base_link 到已定位目标的平面距离 | 成功条件 |
|---|---|---|
| 原单机 | ≤0.81 m | 保留原行为和已有距离停车/补偿规则 |
| 新协同 | 自身 A/B 及本机 C 均 ≤1.00 m | 当前目标接近导航 SUCCEEDED、真实停止确认、任务身份一致、距离达标全部成立 |

协同门槛从入口配置注入，不修改 `config/robot.yaml` 的单机默认值。
候选停车预算、接近补偿和最终验收共用注入门槛：

`路径终点到目标距离 + 当前 Nav2 XY 容差 + 原安全余量 ≤ 当前入口门槛`。

XY 容差0.25 m、余量0.03 m时，门槛0.81/1.00 m分别给出0.53/0.72 m预算上限。
候选无需固定在上限半径；远端候选使用本机全局 costmap、完整 footprint 和规划路径检查；不得仅因候选超出当前局部 costmap 而否决。运动过程中继续使用局部 costmap 避障和资源监护。
协同不能将距离触发的取消或已有近距离直接当成当前接近导航成功。
Nav2 成功但未停稳时只等待，距离不达标时按原次数补偿或失败，不 READY、不完成放入。

不改变 Nav2 容差、0.03 m 原余量、名义停靠距离、footprint、膨胀、过滤阈值、扫描角度、重试次数和既有超时。
共享核心继续读取实际 Nav2 容差，不能用请求目标代替真实路径终点或停稳后的 base_link 位置。
保留调用入口已有总预算（单机一键300秒、协同整任务600秒），不新增或重置每阶段任务计时。
Go2 当前配置的API20秒、单次扫描240秒、握手/失联3秒和既有规划/停车等待预算沿用，Ranger使用其自身接口参数。

## 4. 本地模式、身份与坐标

沿用已有 `share_c_coordinates=false` 和 `SYNC_LOCAL_C`，不新增模式开关、消息字段、话题或动作字符串。
通过已有 kind/target_id/position_valid 的组合表达本地目标级任务，明确记录升级后的命令语义。

新模式不要求 Go2 与 Ranger 数值地图对齐：

- 任务、READY、完成、心跳及资源申请只传身份、阶段、引用和许可，不携带可执行跨机坐标。
- 本机地图文件、版本/摘要、定位、RGB-D/图像时刻 TF、可执行路径与成本图仍须本机有效。
- 机器人身份、task/command/sequence、simulation、schema 和本机地图版本仍受检查；任务内地图身份变化须暂停。
- 本机目标缓存和执行使用本机地图坐标，不经过 common↔local 跨机器人坐标变换。
- C 观测的网络载荷不包含 C 坐标；coordinator 不转换位置，也不绑定共同 C。
- 本轮固定分工无需借用对端 A/B 坐标，新的本地任务模式也不把这些位置用作跨机导航目标。

旧对齐模式的标定检查保留；只为不交换坐标的新模式移除跨地图对齐和远端地图文件依赖。
不能把这一变化扩大为放宽本机标定、地图身份、定位或现场验证。

## 5. 本地资源几何与许可

资源仍由 coordinator 按现有 resource_id/token 互斥管理；两端相同 resource_id 对应同一物理资源，
这个语义须现场核实，但不需要把两端多边形变换到共同数值坐标。

新模式的保护区多边形、门通行退出点和 C 退出点分别取机器人自己的本地配置。
coordinator 维护资源目录和顺序，不发送另一地图中的退出坐标。
缺本机保护区、退出点、候选资产或停止余量继续关闭 live gates，不能用 fake 数据或零值解锁。
EXIT 必须保留原 C 接近主命令的 parent_command_id 和 token；整机退出确认并释放后才完成。

## 6. 命令与状态

新模式以既有 kind/target_id 组合表达目标级本地搜索，承载目标 A/B/C 与任务身份，不承载固定探索点或跨机目标坐标。
搜索 A/B 命令在本地完成探索和接近验收后才回报成功及 READY。
搜索 C 只取得本地可用线索；C 接近/放入仍由阶段与顺序许可控制，不能在 READY 屏障前执行。

C 是否已有本机线索可以通过无坐标状态/观测引用报告；coordinator 据此安排 C 阶段动作，不能替机器人选观察点。
任务切换清空本地缓存；暂停/取消后的迟到 VLM、规划和导航结果不得推进任务。
失联先停止，按原真实停车及 action terminal 条件确认；不自动恢复、不释放仍占用的资源。

五条现有 task 话题及 Reliable/Volatile 定向桥拓扑保持；不桥接 TF、costmap、图像、速度或 action。
交接须列明两端必须同步的命令语义，不能只比较 ROS 字段指纹就认定兼容。

## 7. 相关验证

仅离线/替身检查，不初始化真实 ROS 或硬件：

1. 同样0.90 m、当前接近导航成功且已停稳：单机不能验收成功，协同可以。
2. 协同距离>1.00 m、未确认停稳、导航未成功、旧任务/旧goal结果均不能 READY/完成放入。
3. 候选预算、补偿与最终验收使用同一门槛，验证0.53/0.72 m预算关系及碰撞/路径否决保留。
4. 原单机扫描/接近相关基线；8×45°、新鲜帧/TF、ABC及自身目标提前结束扫描保留。
5. 双 fake 经相同公共接口完成 A/B→READY→各自 C→Go2 退出→Ranger 放入/退出，且无 C 坐标外发。
6. VLM Future 未完成时仍推进心跳；超时、失联或取消后不消费迟到成功。
7. 本地地图可以数值不同、无对齐，仍能交换任务状态；本机地图/资源失效必须拒绝运动。
