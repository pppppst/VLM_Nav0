# Piper 地面抓取可达性初筛（2026-11-06）

## 结论与范围

用户要求继续推进 Go2 单机地面抓取，当前仅做离线分析。按讨论假设：机械臂安装面离地 H=0.60 m，基座中心轴到雷达/护架最前缘水平距离 D=0.50 m，安装面水平。H/D 不是实测标定；假设目标在正前方且不比护架前缘更近，以水平距离 r=0.50 m 做乐观筛查。侧方目标不自动套用这个障碍距离。

补充分析假设：夹持点离地 h=0.05 m，法兰到夹持点的距离 L 分别为 0.10、0.15、0.20 m。h 和 L 均不是用户已确认值，也不是厂家承诺的本机 TCP。依据以下官方候选模型，即使忽略关节限位、自碰撞、环境碰撞和抓取朝向，三种 L 下目标都超过了几何伸展上界。此结论有条件，不能据此断言这台实机在所有站姿和抓取位置都无法抓地面物体。

## 模型与来源

- [官方 SDK 说明](https://github.com/agilexrobotics/piper_sdk)：S-V1.6-3 之后固件使用新的 DH 参数；本次按交接中的 S-V1.8-2 选择 dh_is_offset=1，仍待实机几何标定。

## 计算方法

以安装面对应的候选模型基座原点为参考，肩部中心 S=(0,0,0.123)。实机安装面与模型原点对应关系待核实。

由三角不等式，肩部到法兰的距离不会超过连杆位移长度之和：

```text
A = 0.28503 + sqrt(0.021984² + 0.25075²) ≈ 0.536742 m
B = A + sqrt(0.000088259² + 0.091²) ≈ 0.627742 m
肩部到目标距离 R = sqrt(r² + (H + 0.123 - h)²)
必要条件：R ≤ B + L
```

对 H=0.60、r=0.50、h=0.05，R≈0.838409 m，因此必要条件为 L≥0.210667 m。即使满足它，也可能因关节限位、方向或碰撞而不可达；不建议据此加长夹爪，工具变更还影响负载与碰撞。

| 假设法兰到夹持点 L | 任意朝向的水平距离上界 | 夹爪竖直朝下的水平距离上界 |
| --- | ---: | ---: |
| 10 cm | 27.7 cm | 23.6 cm |
| 15 cm | 39.0 cm | 31.9 cm |
| 20 cm | 48.2 cm | 37.7 cm |

各值均按 H=60 cm、h=5 cm 计算，是乐观上界，不是已验证抓取区。正前方目标若必须在 50 cm 以外，距离增加只会更不利。前侧方是否存在更近且无遮挡的位置，尚无实测障碍尺寸可判定。

竖直朝下的估计另外假设 TCP 沿法兰局部 +Z，给腕部横向约 0.088 mm 偏移留出放宽量。必要条件约为：

```text
sqrt(r² + (H + 0.123 - h - 0.091 - L)²) ≤ A + 0.000088259
```

例如 L=15 cm、r=50 cm、h=5 cm 时，安装面高度必须不超过约 36.3 cm 才能通过这个必要条件；不是建议让 Go2 自动下降到该高度，也未验证对应机身姿态、腿部空间或稳定性。保持 H=60 cm 时，夹持点高度至少约 28.7 cm 才能通过同一朝向上界，仍不是实际可抓保证。

对比图：`build/piper-reachability-20261106/reach_bounds.png`。图中高于曲线的位置可按模型排除；低于曲线不代表可达。

## 验证与模型差异

一次性分析脚本 `build/piper-reachability-20261106/analyze.py` 不导入 ROS/CAN、不调用机器人接口，不是长期操作入口。运行 Python3.10 时仅将官方 FK 源码中的 typing_extensions.Literal 导入替换为标准库 typing.Literal，未改变运动学计算或保存的原始文件，也未安装依赖。

执行结果：零位、已采样当前姿态及固定随机种子的 300 组公开限位内姿态，共 302 组。独立 URDF 矩阵计算与官方 SDK FK 的位置最大差异 0.1375 mm，检查阈值 0.2 mm；每组还核对法兰及三种工具长度下的三角不等式上界，断言通过。数值证据为同目录 `result.json`。这些是离线计算自检，不是新增产品测试或现场验收。

当前实测 J2=-7.740°、J3=+2.129°，而公开 URDF/SDK 默认范围分别为约 [0°,180°]、[-170°,0°]。差异原因未确定，不判定硬件故障、不强行裁剪反馈，也不据此改限位或校零。真实限位、零位和模型对应关系须在生成实机角度前核对。

未执行 IK、路径规划、网格碰撞、抓取力/负载和整机稳定性验证；未连接上位机、启动 ROS 或发送运动。未修改导航、使能服务、环境或安装产物，因此不做产品构建或切换 overlay。

## 用户手动伸展观察（同日后续）

用户随后报告：沿机器人中轴线、从头部相机前方向下伸展，仍距地面约 10 cm 或更多；从头部侧方、肩膀附近向下伸展，距地面约 5 cm。用户进一步确认测量点为夹指最下端（指尖），不是夹持中心。来源为用户现场观察，本机未采样对应关节角、机身姿态或末端坐标。左右哪一侧、准确水平位置、沿途干涉情况及检查后的使能状态均未确认。

这说明在已尝试的姿态中，侧方更接近地面，适合作为下一步优先核对的候选方向；不能把两数值当成完整工作空间的最低高度或自动抓取通过。也不能据此反推前文假设 H/D 已实测正确。物体放在地面不要求夹爪接触地面：是否能侧夹取决于物体可夹持部位与夹指有效接触区域的重叠，指尖离地高度不等于夹持中心高度。低矮物体与较高物体应分别判断，暂未确定首个物体。

侧方方案还须验证头部相机能否在停车后看到目标，以及接近、闭合和抬起是否避开前腿/机身。当前尚未生成侧方导航停车位或抓取轨迹，不自行改变机身高度，不增加新的导航运动门槛。

## 下一步

1. 指尖测量点已确认；下一步检查具体物体的可夹持部位与指面有效接触区域是否重叠，并实测 H/D、法兰到拟夹持中心长度 L、物体尺寸/重量和夹持高度 h。优先记录尺寸，不为了测量发送运动。
2. 若实测仍落在几何上界之外，先比较可绕开雷达的前侧方位置、安装调整或经验证的机身姿态；不让算法通过反复发送轨迹尝试突破物理范围，不自动修改 Go2 站姿。
3. 对通过几何筛查的候选核对真实模型/零位/限位及 TCP，补充 Go2、雷达护架和腿部碰撞空间，再做 IK 和整条路径验证。
4. 后续现场授权下依次做分段空载、固定物体、静止视觉抓取，最后接入现有单机搜索/接近。当前仍未具备可执行的自主抓取轨迹。
